# Contake — תוכנית הספרינט המכווצת: אלפא מתוקנת לקראת שבת (v1.0)
**תאריך:** 17.9.2026 02:40 | **TL** | **מסגרת:** מטרת שבת = יעד תקיפה, לא הבטחה. הגדרת "אלפא מתוקנת" לא זזה: כל שערי האמינות + חמש פסיקות הצירים ירוקות. UI חלקי ≠ אלפא, בכל מצב.

## הנתיב הקריטי האמיתי לשבת (לפי תלויות, לא לפי רצון)
```
FE recovery tarball → QA acceptance ─┐
                                     ├→ FE Builder + content UI → אינטגרציה → E2E → פסיקות
backend §24+§25 → §20 → §22+§23 ────┘   (FE תלוי ב-recovery וב-routes)
execution seed loader ──↑ (אחרי §22/§23)
```
**הצוואר הראשון:** שחזור FE. בלי עץ קנוני שעבר קבלה, אין Builder ואין UI תוכן — שני שלישים משכבה A חסומים. **הצוואר השני:** backend הוא משאב יחיד; הסדר שלו קובע מתי E2E יכול להתחיל. **הצוואר השלישי:** E2E רץ על dev/לוקאלי בלבד (staging קפוא) — ראיות תקפות, אבל כל שער דורש ארtefact מוכן.

## לוח זמנים מקבילי מקסימלי (בטוח)
- **היום (ה׳):** backend מנחית §24 (reports surface) + §25 (inbound opt-out) — הקטנים ביותר, פותחים שני stop-ships; מתחיל §20. Infra+QA: קבלת שחזור FE (מבחן ה-hash מול RC 1789434469015). DL: מסגרת Builder (נכון ל-14:30). E2E: harnesses ל-§24/§25/§20 מוכנים מראש. execution: loader מוכן, ממתין לישויות.
- **מחר (ו׳):** backend מנחית §20 (content+focus/now) ואז §22+§23; FE: Builder על fe/dev מהעץ המשוחזר + UI תוכן בפוקוס; E2E: ראיות §24/§25 בבוקר, §20 אחה״צ; execution: seeds נטענים ברגע שהישויות קיימות; QA: תוויות רצות.
- **שבת:** FE משלים Builder+תוכן, אינטגרציה מלאה מול backend, ריצות E2E לכל הסעיפים, חבילת ראיות לחמשת ה-PQMs. הפסיקות עצמן — ברגע שהראיות קיימות, אצל המנהלים, לא אצלנו.

## תחזית כנה (מעוגנת בארtefacts, תעודכן כשמיילסטונים נוחתים)
- **best-case (שבת בלילה):** כל שכבה A מיושמת + ראיות E2E ירוקות; פסיקות PQMs נמסרות ראשון. תנאים: tarball מגיע היום ועובר קבלה בבוקר; backend מנחית §20-§23 עד ו׳ בערב בלי רגרסיות; אפס הפתעות אינטגרציה.
- **likely:** backend + ראיות מלאים עד שבת; Builder תפקודי אבל אינטגרציית FE↔routes ותיקוני E2E גולשים לראשון; פסיקות מלאות ראשון-שני. אלפא מתוקנת מוכרזת ראשון-שני, לא שבת.
- **blocked:** (א) ה-tarball לא מגיע/נכשל בקבלה → Builder ותוכן-UI קפואים, שכבה A לא נסגרת; (ב) §22 consent/dispatcher מתגלגל רחב מדי (handler STOP בלי route + אכיפה ב-dispatch = נגיעה במסלול מסירה חי); (ג) חלון דמו מתאשר באמצע — הקפאה מלאה על כל הסביבות המשותפות. כל אחד מהם דוחה את כולו.

## מה לא נותנים למטרה לעשות
- לא מחלישים אף שער: §13, §17 (כשמוטמע), QA labels, חמש פסיקות — כולם בתוקף מלא.
- לא מכריזים אלפא על UI חלקי או ראיות חלקיות. ההכרזה היא בינארית.
- לא נוגעים ב-staging ובפרודקשן.
- הערכת ה-4–6 שבועות הקודמת נשארת על שולחנו כ-timeline שמרני; תוכנית זו היא הלחץ המקסימלי הבטוח — אם best-case לא מתממש, נאמר זאת מיד עם הסיבה, לא נצבע את ה-fallback כהצלחה.
